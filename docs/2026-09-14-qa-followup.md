# 호담 2차 QA 및 개선 기록

2026-09-14. 기존 작업을 유지한 채 로그인한 서비스 화면, 실제 저장 데이터, 서버 동작과 회귀 테스트를 함께 검토했다. 운영 데이터 수정, 실제 결제, 새 유료 AI 생성 요청은 수행하지 않았다.

기존 책에 이미 저장된 선택지나 본문을 소급해서 변경하지 않았다. 새로운 선택지 품질 검사는 앞으로 생성하는 책에 적용된다.

## 실제 브라우저 확인

- 로그인한 책장: 검색 결과 없음, 더 보기 24 → 48개, 추가 항목으로 초점 이동, 완성/이전 동화/내용 없는 기록 구분.
- 저장된 완성 그림책: 첫 화면 1–2쪽, End 키로 7–8쪽, Home 키로 첫 쪽, 본문과 기존 삽화, 누락 삽화 안내.
- 이전 형식 동화: 실제 본문 및 기존 삽화 로드. 본문 없는 기록 2개는 DB 조회로도 본문과 메시지가 없음을 확인.
- 내 계정: 실제 정보·사진 로드. 계정 변경과 저장 응답 경합은 테스트로 검증했으며 실제 프로필은 변경하지 않음.
- 결제 내역: 실제 완료·확인 중 내역 및 취소 상태 빈 화면. 새 결제나 승인은 수행하지 않음.
- 곶감: 보유 수량, 패키지 가격, 충전 비활성 상태 확인.
- 모바일 375 × 812: 그림책 한 쪽 표시, 삽화·본문·가격 카드 가로 넘침 없음, 메뉴 열기/Escape/초점 복귀. 테스트 후 화면 크기 설정 복원.

## 검증 결과

- `npm test`: 12개 파일, 177개 테스트 통과.
- `npm run build`: 프로덕션 빌드 및 정적 페이지 생성 통과.
- `npm run typecheck`: 통과.
- `npm run lint`: 오류 없음. 기존 스타일·이미지·순차 비동기 처리 관련 경고는 남아 있음.
- `npm run test:db`: 격리된 로컬 Postgres에서 두 보안 마이그레이션, 소유권·차감·저장소 정책 회귀 검증 통과. 운영 DB에 적용한 검증이 아님.
- `npm audit`: 전체 의존성 취약점 0건.
- 브라우저 번들에 설정된 서버 비밀값이 포함되는지 확인: 노출 없음.
- `git diff --check`: 통과.

명령 결과는 로컬 `.gstack/qa-reports/second-pass/`에 보관한다. AI 오류·응답 유실·동시 요청·계정 전환은 모의 응답으로 검증했다. API 잔액 문제로 신규 책 생성부터 결말까지의 실제 외부 API 성공 검증은 완료하지 못했다.

## 남은 운영 및 구조 개선

1. **OpenAI API 잔액**: 현재 책 결말 실패의 서버 로그에 `429 / credit_balance_exhausted / insufficient_quota`가 기록되어 있었다. 사용자 곶감 잔액과 다른 한도다. API 계정 복구 후 실제 이야기·삽화 생성 및 품질 확인이 필요하다.
2. **운영 DB 보안 마이그레이션 미적용**: 읽기 전용 조회 결과 `image` 버킷은 아직 공개이며, 로그인 역할에 `credit_beads`와 `finalize_payment` 실행 권한이 남아 있다. 아래 준비된 마이그레이션을 서버 배포와 함께 적용해야 한다. 코드만 바뀐 상태에서 운영 권한 문제가 해결되었다고 볼 수 없다.
   - `supabase/migrations/20260914010000_harden_hodam_accounting.sql`
   - `supabase/migrations/20260914020000_private_picturebook_storage.sql`
3. **프로필/결제 서버 설정**: 운영 저장소에 `profiles` 버킷이 없고 결제 설정 확인은 비활성 상태를 반환한다. 준비된 저장소 마이그레이션과 서버 전용 결제 설정을 반영한 뒤 실제 업로드 및 결제 검증이 필요하다.
4. **여러 서버 사이의 생성 예약**: 현재 진행 중 요청 합치기는 서버 프로세스 안에서 작동한다. 저장 충돌과 사용자 차감은 방어하지만 서로 다른 서버에서 같은 AI 작업을 시작하는 비용까지 완전히 차단하지는 못한다. 후속으로 DB의 요청 키·작업 상태·임대 만료를 사용하는 생성 예약과 원자적인 저장/차감/환불 RPC가 필요하다. 상태를 확인할 수 없는 중간 실패는 운영팀 확인 경로를 남겼다.
5. **책장 데이터 규모**: 이번 개선은 렌더링을 24개씩 제한한다. 데이터 조회 자체는 기존 전체 조회를 유지한다. 대규모 책장에는 제목·상황·완성 상태를 별도 필드로 저장하고 서버 검색과 페이지 조회로 전환하는 작업이 필요하다.

운영 DB·배포·결제 계정을 변경하지 않았으며, 검토 전부터 있던 작업 파일도 유지했다.

## 배포 통합 검증 추가

위 결과는 QA 작업 당시 기준이다. 배포 준비 과정에서 최신 main의 OAuth 복구·v1 API·결제 웹훅·운영 점검 스크립트를 통합했다. 최종 통합 결과는 182개 파일의 1,082개 테스트, 타입 검사, ESLint 경고 0개, 프로덕션 빌드, 전체 npm audit 취약점 0건이다. 이전 페이지 컨트롤러 구조만 검사하던 렌더 테스트는 새 화면 조작·계정 경합 회귀 테스트로 대체했다. 기존 중첩 경로 그림·프로필 사진과 새 비공개 저장소의 호환도 검증했다. 운영 배포 및 DB 적용 여부는 배포 기록을 기준으로 확인한다.
