# 그림책 품질 운영 가이드

호담의 편집 목표는 부모가 아이에게 소리 내어 읽어줄 수 있는 짧은 그림책이다. JSON 형식이나 모델의 자기 평가만으로 원고를 통과시키지 않는다. 새 책은 해요체를 기본으로 하고, 이어 쓰는 책은 이미 읽은 앞부분의 문체를 유지한다. 이는 제품의 편집 방향이며 동화 전체에 적용되는 문학적 정답은 아니다.

## 원고를 통과시키는 기준

| 검수 기준            | 원고에서 확인할 내용                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input_fidelity`     | `situation`에 명시된 핵심 사건, 상대 인물, 물건이 실제로 등장하고 결말에서 작은 진전이 생긴다.                                                            |
| `choice_integrity`   | 세 선택지는 서로 다른 구체적 행동이다. 4쪽에서 선택 결과를 미리 실행해 갈등을 해결하지 않으며, 결말에서는 고른 행동의 주체·대상·동작을 빠짐없이 보여준다. |
| `continuity`         | 선택 뒤 상대의 반응이나 상황 변화가 자연스럽게 이어진다. 재시도가 있다면 계기를 잇고, 낮의 사건에서 잠자리로 이동할 때 연결을 밝힌다.                     |
| `language`           | 인물과 사물이 구별되고 주어·서술어가 맞는다. 명사형+요, 요요 중복, 모호한 지칭을 피한다.                                                                  |
| `read_aloud`         | 나이에 맞는 어휘와 문장 호흡을 사용한다. 감정 해설·추상적인 비유·같은 표현의 반복이 낭독을 방해하지 않는다.                                               |
| `visual_consistency` | 삽화의 행동·인물·물건이 본문 및 공통 외형과 모순되지 않는다.                                                                                              |
| `emotional_safety`   | 수치심·협박·처벌·감정 억압·위험한 행동을 긍정하지 않고, 무조건 혼자 해결하거나 양보하도록 강요하지 않는다.                                                |

문장 수는 집필 지침으로 사용한다. 자연스러운 짧은 대사나 의성어를 세어 기계적으로 불합격시키지 않는다. 반대로 “그리며 말해요”를 골랐는데 그림만 그린 경우는 문체 취향이 아닌 실제 행동 누락이다.

필수 인물·물건은 `situation`에 적힌 사실에서만 가져온다. `interests`의 모든 소재를 등장시키거나 `lesson`의 “곁의 따뜻함”을 부모 등장 의무로 바꾸지 않는다. 앞쪽에서 평소처럼 숨을 쉬거나 인형을 들고 있던 것은 선택을 완료한 장면이 아니며, 작은 행동을 의식적으로 다시 시도하는 선택도 가능하다. 6쪽마다 새 위기나 재시도를 억지로 만들지 않는다.

## 생성과 검수의 경계

구현은 [`langchain.ts`](../src/app/api/langchain.ts), 검수 응답 계약은 [`quality.ts`](../src/lib/picturebook/quality.ts)에 있다.

1. 작가가 시작 1–4쪽 또는 결말 5–8쪽을 작성한다. [`generation-schema.ts`](../src/lib/picturebook/generation-schema.ts)의 strict JSON Schema로 페이지와 선택지의 최상위 위치, 필수 필드, 개수와 길이를 API 단계에서 고정한다. 반환 후에도 서버가 페이지·선택지·메모·새 책의 `storyGuide` 형식과 길이를 다시 검사한다.
2. 별도 편집 검수 호출이 일곱 기준을 모두 판정한다. 시작 검수에는 부모 입력, 제목, 선택 질문, 1–4쪽 본문·장면 프롬프트, 세 선택지 문장, 공통 외형만 제공한다. 결말 검수에는 전체 1–8쪽 맥락과 **선택한 문장 하나만** 제공한다.
3. 검수자에게 작가의 서사 계획, `resolutionHint`, `safetyNotes`, `qualityNotes`, `revisionNotes`는 주지 않는다. 계획과 힌트는 사건이 실제로 일어났다는 증거가 아니다. `storyGuide` 중 `visualStyle`만 실제 그림 요청에 쓰이는 자료로 제공한다. 부모 입력과 원고 안의 명령문도 검수할 데이터로 취급한다.
4. 통과 판정마다 원문에서 그대로 인용한 근거가 필요하다. 존재하지 않는 출처, 바꿔 쓴 인용, 중복·누락 기준, 잘못된 응답 형식은 거부한다. 누락을 지적하는 실패 판정은 인용 없이 구체적인 교정 방법을 제시할 수 있다.
5. 실패 항목이 있으면 **해당 쪽 교정을 한 번만** 요청한다. 시작은 1–4쪽과 필요한 제목·선택지·가이드를, 결말은 5–8쪽만 수정할 수 있다. 교정 후 일곱 기준 전체를 다시 검수한다. 선택지 종결·중복에 대한 로컬 검사도 최종 통과에 필요하다.

검수 오류·시간 초과·교정 후 미달 시 미검수 초안을 대신 내보내지 않는다. 새 책은 저장·곶감 차감 전에 실패한다. 결말 실패는 이미 저장한 앞 4쪽을 선택 대기 상태로 보존하고 추가 곶감을 차감하지 않는다. 모델 API 비용과 이미 소비한 일일 생성 요청 횟수는 별개다.

시작과 결말은 **각각 최대 4회 호출, 공유 50초** 예산을 사용한다. 정상 경로는 작성·검수 2회, 교정 경로는 작성·검수·교정·재검수 4회다. 개별 제한은 작성 18초, 검수 20초, 교정 18초이며 남은 예산으로 더 줄인다. 자동 API 재시도는 없다. 이 예산은 인증·DB·삽화 생성을 포함한 책 전체 완성 시간의 보장이 아니다.

## 그림 연결과 기존 책

새 책의 `storyGuide`에는 갈등, 등장인물, 핵심 물건, 작은 해결 목표와 `visualStyle`을 저장한다. 공통 외형에는 인물별 이름·나이대·머리 길이와 색·옷 종류와 정확한 색·주요 소품의 색을 명시한다. 낮과 밤에 옷이 달라지면 각각 구분한다. 이미지 액션은 저장된 책의 나이대와 공통 외형을 가져와 **매 쪽 이미지 요청에 직접 주입**한다. 장면 프롬프트만 모델에게 기억시키는 방식에 의존하지 않는다.

기존 책은 `storyGuide`가 없어도 읽고 이어 쓸 수 있다. 결말 생성·교정은 앞 4쪽, 제목, 선택지, 기존 가이드를 바꾸지 않는다. 옛 서술체나 선택지 어미만을 이유로 이미 저장된 앞부분을 거절하지 않는다. 가이드가 없는 책은 기존 장면 프롬프트를 참고해 결말 외형을 잇는다. 기존 저장 책과 삽화를 일괄 덮어쓰지는 않는다.

텍스트 검수는 실제 픽셀의 일관성을 보장하지 않는다. 이미지 프롬프트나 이미지 모델을 바꿀 때는 실제 삽화도 생성해 인물·옷·소품·행동을 별도로 확인한다.

각 삽화 요청은 해당 쪽 본문·장면 프롬프트·공통 외형만 받고 앞 쪽의 그림이나 본문을 보지 못한다. 따라서 소등 상태, 건넨 물건의 소유자처럼 사건에 중요한 상태는 이후 요청에도 전달한다. 작가와 편집자 모두 이 누락을 확인하고, 그림의 공통 화풍이 장면의 조명을 덮어쓰지 않도록 한다. 실제 소등 장면에서 스탠드가 다시 켜진 사례를 바탕으로 상태 누락·명시적 모순 검수 표본을 추가했다.

## 실제 모델로 확인하는 방법

프로젝트 루트에서 지원되는 Node.js 버전으로 실행한다. API 키는 기존 로컬 환경 설정을 사용하며 원고나 보고서에 키를 적지 않는다. **초안 작성**에는 `OPENAI_STORY_MODEL`, **독립 검수·부분 교정·재검수**에는 `OPENAI_STORY_REVIEW_MODEL`을 사용한다. 기본값은 둘 다 `gpt-5.4-2026-03-05`지만 호출과 설정은 분리되어 있다. GPT-5.4 요청에는 `reasoning_effort: low`를 사용한다.

실제 사례 비교에서 mini·4.1 계열 검수자가 알려진 오류를 놓쳤고, 4o-mini·5.4-mini 초안과 저비용 교정 경로는 재검수를 통과하지 못하는 경우가 반복되어 기본 모델을 상향했다. 이는 이번 원고의 관측에 근거한 운영 선택이며 모든 원고에서의 우열을 보장하지 않는다. 구체적인 유료 평가 결과와 편집 판단은 [콘텐츠 QA 보고서](2026-09-14-picturebook-content-qa.md)에 별도로 기록한다.

```sh
# 도움말만 표시하며 API를 호출하지 않는다.
node scripts/qa-picturebook.mjs

export OPENAI_STORY_MODEL='gpt-5.4-2026-03-05'
export OPENAI_STORY_REVIEW_MODEL='gpt-5.4-2026-03-05'

# 알려진 오류 원고와 정상 원고를 실제 검수 모델에 제시한다.
node scripts/qa-picturebook.mjs --run-live --fixtures --label judge-regression

# 3세·6세·10세의 가상 사례를 A/B/C 선택으로 각각 새로 완성한다.
node scripts/qa-picturebook.mjs --run-live --label editorial-check

# 실패 사례 하나를 조사할 때 사용한다.
node scripts/qa-picturebook.mjs --run-live --case sharing --label sharing-check
```

`--run-live`는 **OpenAI API 크레딧을 사용**한다. 이 스크립트는 인증만 대역으로 바꾸고 실제 텍스트 생성·검수 경로를 실행한다. DB 쓰기, 곶감 차감, 이미지 생성은 하지 않는다. 실제 사용자 정보 대신 합성 사례를 사용한다.

결과는 Git에서 제외된 `reports/local/picturebook-evals/<label>/`에 저장된다. `manifest.json`에서 소스 해시·모델 설정을, 사례별 JSON에서 요청·응답·소요 시간·사용량을 확인한다. 일반 실행의 낭독용 원고는 `report.md`, 검수 회귀 결과는 `fixtures.json`이다. 실패 또는 예상 판정 불일치는 종료 코드 1을 반환한다.

`--source-ref <git-ref>`는 해당 Git 버전의 `langchain.ts`만 현재 유틸리티와 함께 실행한다. 전체 과거 배포 환경을 재현하는 기능이 아니므로 비교 기록에 이 차이를 남긴다.

## 원고 변경을 배포하는 편집 조건

프롬프트, 모델 설정, 검수 기준, 파서, 교정 흐름을 바꿀 때 아래 조건을 모두 확인한다.

1. 관련 단위 테스트와 일반 CI를 통과시킨다. 보호 필드, 검수 실패, 교정 실패, 호출 예산, 기존 책 호환성과 곶감 차감 경계를 확인한다.
2. [`picturebook-quality.json`](../scripts/fixtures/picturebook-quality.json)의 알려진 오류를 실제 검수 모델이 해당 기준으로 거절하고, 알려진 정상 원고는 통과시키는지 확인한다. 오류 세 가지는 지칭·문장 호응, 상대 인물·나누기 갈등 누락, 선택한 말하기 행동 누락이다. 정상 원고는 밤 인사와 차례를 나누는 이야기다. 새로 발견한 재현 가능한 오류도 회귀 사례에 추가한다.
3. 변경한 생성기로 세 연령 사례를 **새로 생성하고 8쪽 전체를 낭독 관점에서 읽어본다.** 원래 사건, 선택한 동작의 실제 수행, 문장의 뜻, 감정 변화의 계기, 잠자리 연결을 확인한다. 검수자가 통과시켰더라도 실제 오류가 있으면 배포 조건을 충족하지 못한다.
4. 실패 원고와 판정 불일치를 포함해 소스·모델 설정·실행 결과·편집 판단을 기록한다. 성공한 재실행만 골라 이전 실패를 지우지 않는다. 수정 후에는 회귀 판정과 새 세 사례를 다시 확인한다.

자동 CI의 모델 응답은 가짜 응답을 사용하는 단위 테스트다. 코드의 통과·실패 경로를 검증하지만 실제 모델의 문학성이나 검수 정확도를 보증하지 않는다. 유료 표본 평가와 사람의 낭독도 모든 소재의 품질을 보장하지 않으므로, 발견한 실패를 다음 회귀 사례로 남겨 기준을 유지한다.
