# 호담 AI 모델 효율 검토

확인일: 2026-10-07. 코드와 OpenAI Docs의 공식 문서를 대조했다. 이 검토에서는 유료 API를 호출하지 않았으며 실제 한국어 품질, 응답 시간, 운영 계정의 모델 접근 권한은 검증하지 않았다.

현재 구성이 가장 효율적이라고 단정할 근거는 없다. 본문·검수·교정 모두 GPT-5.4를 쓰는 기본 구성에는 비용을 줄일 여지가 있다. 다만 저렴한 모델의 검수 누락이나 잦은 교정 때문에 완성본 한 권당 비용이 오를 수도 있다. 우선 호출별 토큰과 시간을 측정하고, 한국어 그림책 평가를 통과한 조합을 선택한다. 이번 변경은 모델을 자동 교체하지 않는다. 집필 요청의 user 메시지에 중복되던 시스템 지침을 제거해, 동일한 지침을 system 메시지에서 한 번만 전달하도록 줄였다. 절감액은 실제 usage 수집 전에는 추정하지 않는다.

## 코드에서 확인한 기본 구성

| 단계                 | 기본 모델·설정                                | 완성본 한 권의 호출 수   |
| -------------------- | --------------------------------------------- | ------------------------ |
| 앞 4쪽과 뒤 4쪽 집필 | `gpt-5.4-2026-03-05`, `reasoning_effort: low` | 2회                      |
| 독립 검수            | 같은 GPT-5.4 스냅샷, low                      | 최소 2회                 |
| 결함 교정·재검수     | 같은 GPT-5.4 스냅샷, low                      | 단계별 필요 시 2회 추가  |
| 페이지 삽화          | `gpt-image-2.5-flare`, low, 1024×1024, PNG    | 재시도 없는 완성본은 8회 |

본문은 `OPENAI_STORY_MODEL`, 검수와 교정은 `OPENAI_STORY_REVIEW_MODEL`, 삽화는 `OPENAI_IMAGE_MODEL`로 바꿀 수 있다. 위 표는 소스의 기본값이며 운영 환경의 실제 override를 뜻하지 않는다. 호출 로그의 model로 실제 요청 설정을 확인한다.

`src/app/api/langchain.ts`의 텍스트 생성은 시작과 결말 각각 최대 4회, 총 50초의 예산을 둔다. 정상 완성 과정은 텍스트 4~8회다. 실패한 시도와 사용자의 재요청은 이 수에 별도로 더해진다. SDK 자동 재시도는 0회다. `src/services/hooks/use-picturebook-images.ts`는 그림을 **한 장씩 순차 요청**한다. 인증 변경과 quota 실패 뒤 추가 지출을 중지하기 위한 구조다. 동시 요청 수를 늘리면 대기시간은 줄어들 수 있지만 이미 진행 중인 과금 요청의 중지는 보장되지 않으므로 별도 검증 없이 변경하지 않는다.

미국 달러, 100만 토큰당 Standard 가격. GPT-6 후보는 short-context 구간이다. 계정별 할인, 세금, 장문 구간, 별도 cache-write 비용은 아래 표에 포함하지 않았다.

| GPT-5.4 Mini | $0.75 |    $0.075 |  $4.50 | 기존 계열의 검수·교정 또는 집필 후보 |

출처: [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [OpenAI API pricing](https://developers.openai.com/api/docs/pricing).

같은 토큰 수라면 5.4 Mini의 텍스트 비용은 현재의 30%다. 이는 **단가 계산**이며 품질 유지, 응답 속도 개선, 책 전체 비용 70% 절감을 입증하지 않는다. 실제 토큰 수·추론량·교정 횟수·삽화 비용이 다르기 때문이다. 특히 현재 호출부는 `gpt-5.4*`만 low reasoning 설정으로 분기한다. GPT-6 후보는 지원 endpoint, 파라미터, structured output, 시간 제한을 먼저 확인하고 호출부 호환성을 구현한 뒤 평가해야 한다. 환경 변수만 바꿔 운영에 적용하지 않는다.

Flare는 공식 문서상 빠른 일상 이미지 생성용 모델이며 text input $5, image input $8, image output $30/100만 토큰이다. 현재 low 설정은 낮은 비용을 의도한 합리적인 출발점이지만 호담의 연속 그림책에서 최선이라는 실측 근거는 없다. [GPT Image 2.5 Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare).

공식 이미지 가이드는 동일 단가라도 모델·품질별 토큰 수가 달라 한 장의 비용이 달라질 수 있다고 명시한다. GPT Image 2나 구형 모델의 출력 토큰 표를 Flare에 대입하지 않는다. 2.5 계산기를 사용할 때도 모델·품질·해상도를 확인해야 하며, 운영 비용은 반환된 usage로 계산한다. 현재처럼 직접 Images API를 호출할 때는 캐시 입력 할인을 가정하지 않는다. [Image generation: costs](https://developers.openai.com/api/docs/guides/image-generation#costs).

## 이번에 추가한 측정

`src/lib/picturebook/model-telemetry.ts`의 `withPicturebookModelTelemetry`는 개별 API 호출을 감싸고 `picturebook_model_call` 서버 로그를 남긴다. 원래 응답과 오류를 호출자에게 그대로 전달하며 로깅 실패가 생성 재시도를 유발하지 않는다.

허용한 필드는 다음뿐이다.

- `model`: 알려진 모델 별칭 또는 날짜 스냅샷. 허용 목록에 없는 설정은 `unrecognized`로 가려 설정에 잘못 들어간 키나 임의 문자열의 노출을 막는다. 새 모델을 채택할 때 목록도 갱신한다.
- `phase`: draft/review/repair/image, `stage`: start/ending/image.
- `elapsedMs`: 해당 API 요청의 경과 시간, `outcome`: success/failure. success는 API 응답 수신을 뜻하며 이야기 검수 통과나 저장 성공을 뜻하지 않는다.
- `usage`: API가 반환한 0 이상의 정수만 기록한다. 텍스트는 입력·출력·합계·캐시 입력·추론 토큰, 삽화는 입력·출력·합계와 텍스트/이미지 세부 토큰이다.

프롬프트, 이름, 이야기, 사용자·책·요청 ID, 이미지, URL, API 키, provider error 메시지는 기록하지 않는다. 없는 usage나 누락된 세부 토큰을 0으로 만들지 않는다. 실패 응답의 usage도 추정하지 않으며 provider billing과 대조할 때 미확인 비용으로 표시한다. 이미지 usage의 세부 필드는 [Images API response](https://developers.openai.com/api/reference/resources/images/methods/generate)를 따른다.

이 로그만으로 개인별 책을 재구성하거나 정확한 한 권의 누적 비용을 연결할 수는 없다. 모델·phase·stage별 사용량과 호출 성공/실패 비율, 지연 분포를 관측하는 목적이다. 완성본당 비용은 동일 평가 실행 구간의 모든 호출 비용을 합산한 뒤 그 실행의 완성본 수로 나누고, 실패한 시도 비용도 포함한다. 운영 측정에서는 로그 보존 범위·샘플링 누락과 완성본 집계 기간을 맞춰야 한다.

## 단계별 비용 계산

텍스트 호출의 입력 I, 그중 캐시 입력 C, 출력 O와 각 단가 p를 알 때:

```text
callUSD = ((I − C) × pInput + C × pCached + O × pOutput) / 1,000,000
textUSD = Σ draft + Σ review + Σ repair
bookUSD = textUSD + Σ image + 확인 가능한 실패·재시도 비용
```

`reasoningTokens`는 출력의 세부 항목이므로 출력 합계에 다시 더하지 않는다. C가 없으면 캐시가 0이었다고 단정하지 않는다. 그 경우 캐시율 미확인으로 남기고, 필요하면 캐시 미적용 단가의 상한 추정치를 실측과 구분해서 제시한다. 서로 모순되는 usage나 가격을 알 수 없는 모델은 계산에서 분리한다.

현재 직접 Images API의 반환값이 입력 텍스트 T, 입력 이미지 V, 출력 이미지 P를 제공한다면 Flare의 비용은 `(T × 5 + V × 8 + P × 30) / 1,000,000`이다. 이미지 전용 응답에서 outputImageTokens가 없을 때 outputTokens를 사용하는 것은 해당 모델의 출력이 이미지 토큰뿐임을 확인한 경우에 한한다. 세부 입력 토큰이나 가격 정보가 없으면 정밀 비용은 미확인으로 둔다.

예를 들어 **실측이 아닌 가정**으로, 재교정 없이 집필 2회·검수 2회가 각각 입력 5,000/출력 2,000토큰, 캐시 0이라면:

| 가상 구성                | 집필 2회 | 검수 2회 | 텍스트 합계 |
| ------------------------ | -------: | -------: | ----------: |
| 전부 GPT-5.4             |  $0.0850 |  $0.0850 |     $0.1700 |
| 집필 GPT-5.4 + 검수 Mini |  $0.0850 |  $0.0255 |     $0.1105 |
| 전부 Mini                |  $0.0255 |  $0.0255 |     $0.0510 |
| 전부 GPT-6.1 Sol         |  $0.0600 |  $0.0600 |     $0.1200 |

이미지 8장, 오류·재시도, 추가 교정, 캐시·세금은 제외한 예시다. 실제 한국어 프롬프트의 토큰 수를 이 가정값으로 대신하지 않는다.

## 크레딧 확보 후 평가 순서

1. **고정 한국어 평가 자료를 만든다.** 실제 아이 정보 없이 연령 3구간 × 일상/모험 2모드 × 상황 4종 = 24개 입력을 준비한다. 이름의 받침, 서로 다른 A/B/C 행동, 낯선 모험 소재, 두 번째 책에서도 같은 단짝 유지, 조용한 결말을 포함한다. 현재 책의 출력만 사용한 편향을 피하고 별도의 보류 사례를 둔다.
2. **검수 모델부터 독립 비교한다.** 사람이 판정한 올바른 원고와 일부러 갈등·조사·선택 행동·외형을 틀린 원고를 같은 비율로 준비한다. 기준선 GPT-5.4와 Mini, 필요하면 Luna를 동일 원고로 비교한다. 원고 생성 모델이 자기 원고를 더 잘 통과시키는지 분리하고, 결함을 통과시키는 비율과 정상 원고의 불필요한 거절률을 모두 기록한다.
3. **집필 후보를 익명 비교한다.** 기준선과 후보 한 개씩 동일 입력·선택을 사용한다. 한국어 낭독 자연스러움, 장면의 재미, 아이의 행동, 선택 반영, 연령 적합성, 단짝의 이름·성격·외형, 끝맺음을 사람이 판정한다. 모델 이름을 가리고 가능한 한 순서를 섞는다. 한 번의 출력으로 최적 모델을 선정하지 않는다.
4. **전체 생성 경로를 측정한다.** JSON/검수 첫 통과율, 교정률, 최종 완성률, phase별 p50/p95 API 시간, 완성본당 총비용, 첫 글·첫 그림·전체 8장 표시 시간을 함께 비교한다. API 시간 합계는 이미지 저장·다운로드·사용자의 선택 대기를 포함한 체감 시간과 다르다. 먼저 텍스트 후보를 줄인 뒤 소수 대표 책에서 삽화 low/medium을 비교해 평가 비용을 통제한다.
5. **선택 기준을 미리 고정한다.** 아동 안전과 입력/선택 위반은 통과시키지 않는다. 익명 낭독 평가와 검수 결함 탐지가 기준선보다 나빠지지 않는 후보 중 완성본당 비용·대기시간이 개선되는 구성을 선택한다. 작은 평가 자료에서 오류가 0개였다는 사실이 무오류를 보장하지는 않는다. 모델 접근·API 계약·timeout을 확인한 후 소량 적용하고 지표가 악화되면 기존 설정으로 되돌린다.

현재 결론은 **Flare low는 유지하고 텍스트 모델의 단계별 비교를 준비하는 것**이다. 모델 이름만 최신으로 바꾸기보다 어느 단계에서 비용이 생기고, 저렴한 대안이 같은 한국어 품질을 지키는지 먼저 확인한다.

## GPT-5.4와 Luna/Sol 실제 비교 실행

2026-10-07 후속 비교는 기준선 `GPT-5.4 집필 + GPT-5.4 검수·교정`과 후보 `GPT-6 Luna 집필 + GPT-6.1 Sol 검수·교정`을 대상으로 한다. 공식 가격과 기존 연동 비용을 고려한 후보 선택이며, 한국어 동화 품질의 실측 우위를 뜻하지 않는다. 운영 모델 기본값은 변경하지 않았다.

```sh
# API를 호출하지 않는 구성·번들 확인
npm run qa:models -- --dry-run --label prepared

# 유효한 OPENAI_API_KEY를 .env.local에 설정한 뒤 실행
npm run qa:models -- --run-live --label comparison-2026-10-07 --max-usd 10

# 같은 소스·사례·예산으로 중단된 실행을 이어가기
npm run qa:models -- --run-live --label comparison-2026-10-07 --max-usd 10 --resume
```

- 실제 생성·교정·검수 코드와 프롬프트, 단계별 50초 제한을 재사용한다. 인증은 합성 사용자로 대체하고 DB와 이미지 API는 호출하지 않는다. GPT-6 호환 파라미터 변경은 격리된 평가 클라이언트에만 적용한다. 두 구성 모두 `low` 추론, 출력·추론 합계 6,000토큰 상한, Standard tier, SDK 재시도 0회를 사용한다. 출력 상한은 운영과 다른 평가 조건이며 `length` 종료는 실패로 기록한다.
- 연령 3구간 × 일상/모험 2모드 × 사례 4종으로 총 24개다. 실제 아이 정보 없이 동일 입력·선택 ID를 비교한다. 생성된 선택 행동 자체는 각 원고마다 다를 수 있다. 첫 사례의 양쪽 생성이 완료되지 않으면 일괄 실험을 멈춘다.
- 첫 사례 다음에는 정상/결함 고정 원고 9개를 양쪽 검수 모델로 평가한다. 검수 정답률·누락·오탐을 기록한 뒤 나머지 생성 사례를 진행한다. 호출별 모델·시간·사용량, 교정 횟수, 실패 비용을 포함한 완성본당 비용을 남긴다. 모델 자체 검수 통과율은 독립 문학 품질 점수가 아니다.
- 요청 전에 입력 UTF-8 바이트 수와 출력 상한, 단가로 비용을 보수적으로 예약한다. 10달러 이하 예산만 허용하며 인증·권한·quota·rate-limit 실패 시 중단한다. 타임아웃 또는 사용량 누락은 0달러로 처리하지 않고 예약액을 유지한다. 캐시·쓰기 사용량이 불명확하면 비용 범위를 표시한다. 세금과 다른 실행/프로젝트의 지출은 이 예산에 포함되지 않는다.
- 결과는 git에서 제외된 `reports/local/model-comparisons/<label>/`에 저장한다. `report.md`와 `summary.json`은 수치, `calls.json`은 합성 생성 응답, `blind-review.md`는 모델명을 가린 원고, `blind-mapping.json`은 판별표다. 독립 낭독 평가를 완료한 뒤에만 품질 결론을 내린다. `--resume`은 인증·크레딧·연결·공급자 5xx 실패만 재시도하며 기존 결과와 비용 원장을 보존한다. 성공·품질·시간 초과·예산·계측 실패 항목은 재실행하지 않는다. 중단 당시 사용량을 알 수 없는 호출의 예약액도 이어받는다.

초기 접근 확인에서는 로컬 키가 `401 invalid_api_key`로 거절됐다. 이 결과는 잔여 크레딧이나 모델 품질을 보여주지 않는다. 유효한 키로 갱신한 뒤 평가를 실행해야 한다.
