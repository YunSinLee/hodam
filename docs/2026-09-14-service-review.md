# 호담 서비스 검토 및 개선 기록

검토일: 2026-09-14. 기존 작업 중이던 그림책 기능을 이어서 개선했다. 로컬 코드·의존성·브라우저와 연결된 Supabase의 구조·권한을 검토했으며, 운영 데이터 변경·결제·배포는 실행하지 않았다.

## 제품 방향과 화면

서비스를 **아이의 하루를 담아 부모와 함께 읽는 8쪽 잠자리 그림책**으로 정리했다. 기존 홈은 키워드·다국어 동화를 설명했지만 작업 중인 제품은 상황 입력 → 4쪽 → 행동 선택 → 결말 4쪽이었다. 홈의 설명, 입력 화면, 책장, 가격 설명을 실제 흐름에 맞췄다.

- 홈: 종이색, 짙은 초록, 적갈색으로 색을 통일하고 기존 호랑이를 책 표지에 사용했다. 주 행동은 그림책 만들기, 보조 행동은 로그인 없는 미리보기다. 없는 튜토리얼 영상과 과도한 장식을 없앴다.
- 상황 예시: 양치, 친구와 나누기, 어두운 밤. 이름·나이를 유지하면서 상황과 전하고 싶은 마음을 채운다.
- 미리보기: 실제 읽기 컴포넌트로 8쪽과 세 가지 선택을 체험한다. 이 예시는 미리 작성한 글이며, 유료 AI 생성 결과나 계정에 저장된 책이라고 표시하지 않는다.
- 입력: 이름 대신 별명 사용 안내, 나이 3~12세, 항목별 라벨·길이 제한·유효성 안내. 로그인 이동 때 작성 내용을 같은 탭에 2시간 보관하고 돌아오면 복원한다.
- 읽기: 모바일 1쪽, 넓은 화면 2쪽. 화면 크기가 바뀌어도 페이지 짝이 어긋나지 않는다. 큰 글씨, 기기 음성 읽기, 이야기 파일 다운로드, 저장된 책 주소 복사를 제공한다. 그림이 늦거나 실패해도 글을 읽을 수 있다.
- 책장: 제목·아이 이름·상황 검색, 완성/이어 만들기 필터, 선택 전 책의 결말 이어 만들기, 누락된 그림 다시 요청. 빈 책장과 불러오기 실패를 구분한다.
- 계정·결제: 통일된 화면, 실제 로그아웃, 이름·사진 변경, 결제 상태별 조회, 실패 안내와 다시 불러오기. 임의의 할인 표시와 사용자에게 불필요한 결제키 표시는 제거했다.
- 공통: 모바일 메뉴의 키보드 조작, 본문 바로가기, 포커스 표시, 오류·없는 페이지 안내, 경로별 제목, 개인 페이지 검색 제외. 노출되던 `/hodam` 개발용 문구는 홈으로 연결한다.

사용자 입력은 서버에서도 검증한다. 곶감 1개에는 첫 이야기와 결말이 포함되고 결말 선택에 추가 차감하지 않는다. 그림 요청은 직렬로 진행하며 실패한 그림만 다시 요청할 수 있다.

## 운영 반영 전 필요한 작업

이 부분은 **수정안이 준비됐지만 운영에는 아직 반영하지 않았다.**

1. **서버 API 키 교체와 재배포**: 기존 next.config.js가 OpenAI 키를 클라이언트 빌드에 포함하도록 설정했다. 과거 배포물 노출 여부는 별도 확인하고, 해당 키를 교체한다. 새 키는 서버 환경변수로만 저장한다.
2. **회계 권한 마이그레이션 적용**: `supabase/migrations/20260914010000_harden_hodam_accounting.sql`. 현재 연결된 DB의 `credit_beads`, `finalize_payment`에는 브라우저가 호출할 수 있는 권한이 있고, 곶감 차감·쿼터 함수의 사용자 ID 검증도 부족했다. 서버 코드를 바꿔도 직접 DB 호출 권한은 남으므로 SQL 적용이 필요하다.
3. **그림·프로필 저장소 권한**: `supabase/migrations/20260914020000_private_picturebook_storage.sql`. 공개 image 버킷을 비공개로 바꾸고 다른 사람의 그림 조회·변경·삭제를 차단한다. 기존 공개 object URL은 더 이상 열리지 않지만 앱은 서명 URL을 사용한다. 없던 profiles 버킷을 비공개로 만들고, 새 프로필 사진은 경로를 저장한 뒤 서명 URL로 조회한다.
4. **서버 결제 설정**: `SUPABASE_SERVICE_ROLE_KEY`, Toss secret/client key가 필요하다. 검토 시 service role key가 없어서 새 화면은 충전을 준비 중으로 안내한다. 결제 서버 변경과 DB 권한 회수를 함께 배포한다. 기존 브라우저 결제 구현은 권한 회수 후 동작하지 않는다.
5. **데이터 사전 점검**: 마이그레이션의 요청 ID 고유 인덱스는 기존 중복이 있으면 실패한다. 사용자 데이터를 자동 삭제하지 않는다. 기존 completed 결제의 credited_at/credited_user_id 누락은 실제 지급·Toss 승인 기록과 대조해야 한다.
6. **실제 연동 검증**: Google/Kakao 로그인, 신규 사용자의 계정·초기 곶감 생성, 실제 AI 글·그림 1권, 저장된 이미지 재조회, Toss 테스트 결제 및 재확인. 유료 AI 요청과 결제는 이번 검토에서 실행하지 않았다. 모델의 계정별 사용 권한도 확인해야 한다.

Supabase 운영 점검에는 Postgres 패치와 유출 비밀번호 검사 설정도 남아 있다. `payment_webhook_transmissions`는 RLS가 꺼져 있었지만 조회한 anon/authenticated 테이블 권한은 없었다. 이를 공개 데이터 유출로 단정하지 않고 RLS를 추가하는 수정안만 포함했다.

현재 서버 액션은 영속 작업 큐가 아니다. 서버 프로세스 종료나 함수 시간 제한 중단까지 완전히 복구하는 작업 저장소·재처리 워커는 별도 구현이 필요하다. 일반 요청 실패와 모호한 저장 결과는 재확인하지만, 모든 장애 상황에서 자동 환불된다고 약속하지 않는다. 호스팅 플랜이 180초 함수 실행을 지원하는지도 확인한다.

## 다음 기획 판단

- 먼저 확인할 지표: 홈 → 입력 시작, 입력 완료 → 로그인 복귀, 첫 4쪽 생성 성공률, 선택률, 8쪽 완독률, 책장 재방문. 실제 측정값은 아직 없다.
- 가격은 기존 1권 1곶감·곶감당 500원을 유지했다. 모델별 실제 생성비, 그림 실패·재시도 비용, 읽기 만족도를 확인한 뒤 가격과 이미지 품질을 결정한다.
- 생성 결과의 캐릭터 일관성은 텍스트 프롬프트에 의존한다. 그림 품질 검증 후 공통 캐릭터 참조 이미지를 사용하는 편집 흐름을 검토한다.
- 계정 탈퇴·삭제, 공개 공유, PDF 인쇄는 아직 구현하지 않았다. 책 주소 복사는 같은 계정에서 여는 기능임을 표시한다.
- 개인정보·약관 문서는 읽어보았지만 법률 적합성 검토를 마친 것은 아니다. 실제 수집 항목, 아동 정보, 외부 AI 처리, 보관·삭제와 환불 운영을 사업자가 확정한 뒤 문서를 맞춰야 한다. 자동으로 새 약관이나 환불 약속을 만들지는 않았다.

## 검증 기록

- 앱 테스트: **62개 통과**. Vitest로 입력·저장 데이터 검증, 복귀 경로, 읽기/선택/화면 크기 전환, 생성·저장·재시도, 결제 소유자·금액·지급·타임아웃, 이미지 API 계약을 검사한다.
- 정적 검증: `npm ci`, `npm run lint`(오류 0, 스타일 등 경고는 남음), `npm run typecheck`, `npm run build` 통과. Next.js 15.5.25, Vitest 4.1.11. `npm audit`은 전체 0건(검사 시점 기준). 로컬 Node 20.16에서는 일부 개발 도구의 엔진 경고가 있으므로 Node 22.13 이상을 권장한다.
- 빌드 보안: `.next/static`을 실제 구성된 서버 비밀키 두 개의 값으로 검색해 일치 0건. 값 자체는 출력하거나 기록하지 않았다.
- HTTP: 주요 페이지 응답 정상, 없는 페이지 404, 인증 없는 결제·TTS API 401, 미설정 결제 enabled=false 확인.
- DB 테스트: `npm run test:db`. 운영 연결 없이 새 로컬 PostgreSQL 클러스터를 만들고 기존 곶감 함수 정의에 마이그레이션을 두 번 적용한다. 권한 회수, 타인 차감 거부, 중복 차감 방지, 쿼터, 초기 잔액 조작 거부, 요청 ID 중복 거부, RLS와 다른 사용자의 그림 조회·수정·삭제 및 프로필 업로드 거부를 검증한다. 테스트 후 클러스터를 종료·삭제한다. 검증 환경은 로컬 PostgreSQL 14.19, 연결된 운영 환경은 15 계열이었다.
- 브라우저: Codex 인앱 브라우저에서 데스크톱과 375×812 모바일로 홈, 상황 입력, 미리보기 선택→결말→완독, 로그인 안내, 입력 복원, 모바일 메뉴 Escape 닫기, 결제 로그인 복귀 주소를 확인했다. 확인한 홈·읽기 화면의 가로 넘침과 브라우저 오류는 없었다.
- 실제 인증 계정으로 저장·충전하는 흐름은 서버 테스트로 검증했다. 실서비스 전체 연동을 통과했다는 뜻은 아니다.
