# 계정별 즐겨찾기·이어 읽기 저장 계약

`20261008030000_reading_state_sync.sql`을 앱 배포 전에 적용한다. 기존 그림책이나 곶감, 모델 설정은 변경하지 않는다. 서버 저장소가 아직 준비되지 않은 경우 API는 503을 반환하며 성공으로 처리하지 않는다.

## API

두 경로 모두 로그인 토큰과 `x-hodam-owner-id` 헤더가 필요하다. 헤더가 없으면 400, 로그인 계정과 다르면 409로 거절하여 이전 계정 화면의 요청을 새 계정에 적용하지 않는다. 응답은 오류를 포함해 `Cache-Control: private, no-store`다.

- `GET /api/v1/reading-library?after=<책 ID>`: 로그인 계정의 `reading_state`만 책 ID 오름차순으로 최대 200개 조회한다. `after`는 생략하거나 양의 안전한 정수여야 한다. 201개를 조회해 다음 행이 있을 때만 마지막으로 반환한 책 ID를 `nextCursor`로 보낸다. 빈 배열은 실제 조회 성공인 경우에만 반환한다.
- `PUT /api/v1/threads/<책 ID>/reading-state`: 소유한 그림책인지 확인한 뒤 `ReadingStateInputSchema`에 맞는 favorite 또는 progress 한 필드만 저장한다. 임의 속성·아이 정보·클라이언트 시각은 받지 않는다.
- 현재 제한: 조회는 계정당 60회/분, 저장은 180회/분이다. 대량의 기존 기기 기록을 옮길 때 429를 만나면 미완료 요청을 유지하고 나중에 재시도한다.

입력과 응답 스키마는 `src/lib/picturebook/reading-state.ts`가 공통 계약이다. 저장 응답 `{ book, applied }`의 `book`은 DB에서 확정된 상태다.

## 충돌과 책의 확장

즐겨찾기와 읽기 위치는 각각 `favoriteVersion`, `progressVersion`을 가진다. 클라이언트는 수정할 필드의 현재 버전을 `expectedVersion`으로 보내며, 같은 값이어도 정상 적용된 요청마다 해당 버전만 1씩 증가한다. 읽기 위치의 시각은 DB가 정한다.

다른 기기의 변경으로 버전이 달라졌다면 쓰지 않고 HTTP 200 `{ applied: false, book: 최신 상태 }`를 반환한다. 오래된 변경을 최신 버전으로 무조건 다시 보내지 않는다. 응답이 유실된 요청을 같은 버전으로 재전송해도 새 상태를 덮어쓰지 않는다. 즐겨찾기의 변경은 읽기 위치의 버전과 충돌하지 않는다.

기존 4쪽 초안의 책갈피는 결말 저장 후 8쪽 그림책에 가져올 수 있다. 입력 `pageCount`가 실제 쪽수보다 작거나 같고 위치가 입력 범위 안이면 실제 쪽수로 정규화한다. 이전 짧은 쪽수의 `completed`는 false로 바꾼다. 현재 쪽수보다 큰 기록은 409 `READING_BOOK_CHANGED`로 거절한다. 현재 쪽수와 같은 입력에서 완독은 완성된 그림책의 마지막 쪽 또는 마지막 두 쪽 펼침 위치에서만 허용한다.

## DB 경계와 수명

- `(user_id, thread_id)` 기본 키에 즐겨찾기, 쪽 위치/전체 쪽수, 완독 여부, 서버 시각, 두 버전만 저장한다. 이름·제목·본문·삽화 URL은 포함하지 않는다.
- RLS는 조회·생성·수정 모두 현재 사용자와 책 소유자를 확인한다. 사용자 권한은 기본값을 사용하는 `INSERT(thread_id)`와 `UPDATE(favorite,page_index,page_count,completed)`뿐이다. ID, 버전, 시각은 클라이언트가 직접 쓸 수 없다.
- `save_reading_state`는 `SECURITY INVOKER`로 동작한다. 기본 행 삽입 후 해당 행을 `FOR UPDATE`로 잠그고, 요청 필드의 버전을 비교해 갱신한다. 첫 행은 두 버전 0에서 시작하므로 기대 버전 0만 적용된다.
- 각 `BEFORE UPDATE OF` 트리거가 필드별 버전을 올린다. 직접 테이블 UPDATE도 버전 증가를 우회하지 못한다. 버전의 정수 범위를 소진하면 오류로 거절하며 순환하거나 잘못된 버전을 반환하지 않는다.
- 익명 사용자는 테이블과 저장 RPC를 실행할 수 없다. 그림책 삭제 시 FK `ON DELETE CASCADE`로 읽기 상태도 삭제된다. 브라우저 데이터 삭제는 서버 상태를 삭제하지 않는다.

## 브라우저의 저장과 재연결

`reading-sync.ts`는 계정별 공유 저장소를 사용한다. 같은 화면의 여러 컴포넌트가 동시에 읽더라도 조회와 쓰기를 합치고, 마지막 구독이 해제되면 진행 중인 요청을 취소한다. 다른 계정으로 바뀐 뒤 늦게 도착한 응답은 새 계정 화면에 적용하지 않는다.

`hodam-reading-sync:v2:<계정 ID>:cache`는 확인된 서버 기록의 사본이다. `<동일 접두사>:pending:<책 ID>:<필드>`에는 아직 저장되지 않은 사용자 변경을 보관한다. 연결 복구·창 복귀·명시적 재시도 때 계정 기록을 다시 조회하고 저장한다. 단순히 새 서버 값을 읽었다는 이유로 오래된 대기 변경의 기대 버전을 올리지 않는다. 같은 기기의 요청을 보내는 동안 뒤따른 사용자 조작은 앞선 요청의 성공을 확인한 뒤 순서대로 반영한다.

예전 `hodam-reading-library:v1:<계정 ID>`는 읽기용으로 남긴다. ‘계정에 옮기기’를 누르기 전에는 전송하지 않으며, 가져올 때도 서버에 이미 수정 이력이 있는 필드는 유지한다. ‘지금은 안 할게요’는 현재 세션의 안내를 접고, 남은 기록이 기기에만 있음을 표시한다. 큰 글씨·잠자리 모드는 동기화 대상이 아니다.

브라우저 저장이 차단되어도 온라인 계정 저장을 시도할 수 있지만, 계정에 반영되기 전에 페이지를 닫으면 메모리에만 남은 변경은 사라질 수 있다. 화면에 이 제약을 안내한다. 서버에 반영된 기록은 사이트 데이터를 삭제한 뒤에도 유지된다.

## 검증 범위

API 회귀 테스트는 인증·계정 변경·소유권·본문 검증·페이지 범위·4→8쪽 정규화·완독 조건·200개 keyset·저장소 오류와 버전 충돌 응답을 검증한다. 격리된 `npm run test:db`는 마이그레이션 재적용, RLS/열 권한, stale/retry, 같은 값의 버전 증가, 독립 필드, 삭제 수명, 버전 범위 소진을 검증한다. 두 PostgreSQL 연결을 동시에 실행해 같은 버전의 수정은 하나만 적용되고 서로 다른 필드의 수정은 모두 유지됨을 확인한다. 이 검증은 운영 데이터나 유료 AI API를 사용하지 않는다.
